Install

One marketplace for Claude Code, a one-liner for Codex and Cursor, then start with /ask-insurance.

Add the marketplace, install the plugin, reload plugins, then use slash commands.

/plugin marketplace add letslego/insurance-agent-skills
/plugin install insurance-agent-skills@insurance-agent-skills
/reload-plugins

CLI: claude plugin marketplace add letslego/insurance-agent-skills then claude plugin install insurance-agent-skills@insurance-agent-skills

Copy editable skills with skills.sh:

npx skills@latest add letslego/insurance-agent-skills

Or clone the repo and enable Insurance Agent Skills from Codex /plugins (see .codex-plugin/plugin.json).

Any Agent Skills–compatible harness:

npx skills@latest add letslego/insurance-agent-skills

Or clone and point your agent at the skills/ directory.

Deploy at scale

Skills are playbooks. Scale needs pinned distribution, orchestrators, ground-truth context, and a staged rollout.

1. Package & pin

Mirror the pack privately. Install via Claude marketplace, npx skills add org/repo@tag, or submodule. Pin semver — never float latest in production.

Sample: install-pinned.sh + promoted-skills.json

2. Orchestrate

Expose orchestrators (/intake-and-triage, /underwrite-submission), not the whole catalog. Run via Cursor / Claude / Codex desks or SDK / CLI workers on a queue.

Sample: CLI worker + SDK runner + queue stub

3. Ground truth

Every job mounts manuals, authority matrices, and channel allowlists. Pair lookups with /guideline-cite. No improvising policy language.

Sample: build-run-context.py

4. Roll out in rings

Pilot one LOB → shadow next to humans → assist (draft only) → automate low-risk paths. Escalate the rest with /handoff-brief.

Sample: rings.json + ring_router.py

5. Operate

Golden-file evals, skill-version audit logs, escalate/override metrics, and a kill switch (disable orchestrator or pin the previous tag).

Sample: eval_suite + audit_log + guardrails

6. Write back

Emit structured packages (triage memo, UW decision, RFI) into claims/UW systems after human review — or auto-route only where policy allows.

Sample: parse_triage + claims_core_client

Core systems  →  Agent runtime (pinned skills + manuals/RAG)
                         ↓
              Structured out (triage / memo / handoff)
                         ↓
              Human review / core writeback
  • Skills pinned by tag in every environment
  • Only promoted orchestrators exposed per desk/channel
  • Guidelines + authority matrix injected every run
  • Shadow → assist → automate
  • Audit log of skill version + outputs
  • Kill switch ready

Full write-up in the README — Deploy at scale. Runnable samples: examples/deploy-at-scale.

Decision support, not bind authority

These skills structure analysis and write-ups. They do not replace carrier guidelines, authority matrices, actuarial models, or licensed professional judgment. Put your manuals in context so answers can be cited.
